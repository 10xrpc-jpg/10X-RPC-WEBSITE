# 🚀 10X RPC — Render Backend Deployment Guide

This guide details how to deploy the 10X Discord RPC backend on [Render.com](https://render.com).

---

## 🏗️ Architecture Overview

There are two recommended ways to deploy:

### Option A: All-in-One on Render (Simplest & Recommended)
Render runs the full Next.js application, including the frontend UI, OAuth routes, API, and the persistent Discord Gateway RPC WebSocket connections.
- **Frontend URL**: `https://your-service.onrender.com`
- **Backend URL**: `https://your-service.onrender.com`

### Option B: Split Architecture (Vercel Frontend + Render Backend)
- **Vercel** hosts the static frontend edge.
- **Render** runs the backend API and handles long-lived WebSocket connections to Discord.
- Set `RENDER_API_URL="https://your-service.onrender.com"` in Vercel to automatically reverse-proxy `/api/*` and `/auth/*` to Render.

---

## 📦 Deployment via Render Blueprint (One-Click)

The repository includes a ready-to-use [render.yaml](file:///home/sanjay007/Documents/10X-RPC-WEBSITE-OAUTH/render.yaml).

1. Push your repository to GitHub or GitLab.
2. Go to the [Render Dashboard](https://dashboard.render.com/).
3. Click **New +** -> **Blueprint**.
4. Connect your repository. Render will automatically detect `render.yaml`.
5. Fill in the required environment variables prompted by Render (see list below).
6. Click **Apply**.

---

## 🛠️ Manual Web Service Setup (Alternative)

If you prefer to configure the Web Service manually on Render:

1. Click **New +** -> **Web Service**.
2. Connect your GitHub repository.
3. Configure the following settings:
   - **Name**: `10x-rpc-backend`
   - **Environment / Runtime**: `Node`
   - **Region**: Any (e.g., `Oregon (US West)` or `Frankfurt (EU)`)
   - **Branch**: `main` (or your active branch)
   - **Build Command**:
     ```bash
     npm install && npx prisma generate && npm run build
     ```
   - **Start Command**:
     ```bash
     npm run start
     ```
   - **Plan**: `Starter` (or `Free`)
   - **Health Check Path**: `/health`

## 🔑 Environment Variables

Set these environment variables in your Render service dashboard under **Environment**:

| Variable | Description | Example / Recommended Value |
|---|---|---|
| `NODE_ENV` | Environment mode | `production` |
| `DATABASE_URL` | Neon PostgreSQL pooled connection string | `postgresql://user:pass@ep-xyz-pooler.neon.tech/neondb?sslmode=require` |
| `DATABASE_URL_UNPOOLED` | Neon PostgreSQL unpooled direct connection string | `postgresql://user:pass@ep-xyz.neon.tech/neondb?sslmode=require` |
| `SESSION_SECRET` | 48-byte random key for HMAC session cookies | *(Auto-generated by Render or `openssl rand -base64 48`)* |
| `NEXT_PUBLIC_APP_URL` | Public URL of your web app (Render or Vercel) | `https://10x-rpc-backend.onrender.com` |
| `DISCORD_CLIENT_ID` | Discord Developer Portal Client ID | From Discord Dev Portal |
| `DISCORD_CLIENT_SECRET` | Discord Developer Portal Client Secret | From Discord Dev Portal |
| `DISCORD_BOT_TOKEN` | Discord Bot Token (optional/gateway) | From Discord Dev Portal |
| `DISCORD_REDIRECT_URI` | Exact OAuth2 redirect URI | `https://10x-rpc-backend.onrender.com/auth/callback` |
| `DISCORD_OAUTH_SCOPE` | Required OAuth scopes | `openid identify sdk.social_layer_presence` |
| `ROTATOR_TICK_SECRET` | Secret token for `/api/rotator/tick` | *(Random string to secure cron ticks)* |

## 🎮 Discord Developer Portal Setup

1. Open the [Discord Developer Portal](https://discord.com/developers/applications).
2. Select your Application (or create a new one).
3. Under **OAuth2** -> **General**:
   - In **Redirects**, click **Add Redirect**.
   - Add your production callback URL:
     ```text
     https://<your-render-service-name>.onrender.com/auth/callback
     ```
   - If using split Vercel + Render: add `https://<your-vercel-domain>/auth/callback`.
   - Click **Save Changes**.

## 💓 Health Check & Keep-Alive (Free Tier)

Render free web services spin down after 15 minutes of inactivity. To keep your service active 24/7:

1. Render automatically pings `/health` to verify deployment health.
2. You can set up a free monitor (e.g. [UptimeRobot](https://uptimerobot.com/) or Cron-job.org) targeting:
   ```text
   https://<your-render-service-name>.onrender.com/health
   ```
   every 5 to 10 minutes.
3. Alternatively, run the included ping script:
   ```bash
   ./scripts/ping-render.sh
   ```
